## 三、目录 / 包结构

```
com.keshe.edumanage
├── EdumanageApplication        启动类
├── cas/                        CAS 单点登录（规划中）
├── common/                     通用模块
│   ├── exception/              异常（BusinessException、GlobalExceptionHandler）
│   └── result/                 统一返回（Result、ResultCode）
├── config/                     配置类（Cors / Security / MybatisPlus / Swagger / Jwt）
├── controller/                 控制器（REST 接口层）
├── dto/                        请求参数对象（入参）
├── entity/                     实体类
│   ├── BaseEntity.java         公共基类（id、createTime、updateTime）
│   ├── base/                   教学基础数据
│   ├── system/                 系统用户 / 角色
│   ├── exam/                   考务管理
│   ├── graduate/               毕业 / 专升本
│   └── attendance/             考勤管理
├── mapper/                     数据访问层（按业务模块分子包，与 entity 对应）
├── service/                    业务接口 + 实现
├── util/                       工具类（JWTUtil 等）
└── vo/                         返回结果对象（出参）
```

**约定：包名一律用单数**，不要写成 `controllers` / `services` / `mappers` / `utils` / `entities` / `vos` / `dtos`。
目录与包声明必须一一对应（`entity.base.Teacher` → 目录 `entity/base/Teacher.java`），否则会出现「程序包不存在」或「找不到符号」。

## 四、分层架构

调用链路：

```
Controller → Service（接口 + 实现）→ Mapper → Entity（表）
    │                                        │
   dto（入参）                              vo（出参）
```

各层职责与约束：

| 层 | 职责 | 禁止 |
| --- | --- | --- |
| Controller | 接收请求、参数校验、调用 Service、返回 `Result` | 直接写业务逻辑、直接调 Mapper |
| Service | 业务逻辑、事务 | 直接操作 HttpServletRequest/Response |
| Mapper | 仅数据访问，继承 `BaseMapper<T>` | 写业务逻辑 |
| Entity | 与表一一对应，`@TableName` 映射 | 塞入请求/响应无关字段 |

- **DTO**：接收前端入参（如 `LoginDTO`）。
- **VO**：向前端返回数据（如 `LoginVO`、`UserVO`）。
- 实体与 VO/DTO 分离，不直接把 Entity 暴露给前端时请用 VO 转一层。

## 五、命名规范

### 5.1 类名

| 类型 | 命名 | 示例 |
| --- | --- | --- |
| 实体 | 表名去掉前缀 + 驼峰 | `base_teacher` → `Teacher` |
| Mapper | `实体名 + Mapper` | `TeacherMapper` |
| Service 接口 | `实体名 + Service` | `UserService` |
| Service 实现 | `实体名 + ServiceImpl` | `UserServiceImpl` |
| Controller | `实体名 + Controller` | `UserController` |
| DTO | `用途 + DTO` | `LoginDTO` |
| VO | `用途 + VO` | `LoginVO` |

### 5.2 方法名

- 查询单个：`getByXxx` / `findByXxx`（接口、实现、调用处保持一致）。
- 列表：`listXxx`；分页：`pageXxx`。
- 增删改：`save` / `remove` / `update`。

### 5.3 数据库映射

- 表名：`@TableName("xxx")` 显式声明。
- 字段下划线转驼峰由 MyBatis-Plus 自动完成（`map-underscore-to-camel-case: true`）。
- 公共字段 `id` / `createTime` / `updateTime` 由 `BaseEntity` 统一提供，实体 `extends BaseEntity` 并加 `@EqualsAndHashCode(callSuper = true)`。

## 六、统一返回结果

所有接口返回 `Result<T>`，不要直接返回裸对象。

```java
return Result.success(data);        // 成功，带数据
return Result.success();            // 成功，无数据
return Result.error(message);       // 失败（500）
return Result.error(code, message); // 自定义错误码
return Result.fail(message);        // 失败（500，与 error 等价）
```

状态码常量统一用 `ResultCode`（`SUCCESS=200`、`PARAM_ERROR=400`、`UNAUTHORIZED=401`、`FORBIDDEN=403`、`NOT_FOUND=404`、`ERROR=500`）。

---

## 七、异常处理

- 业务异常抛 `BusinessException`，由 `GlobalExceptionHandler`（`@RestControllerAdvice`）统一捕获并转成 `Result`。
- 不要在 Controller 里到处 `try/catch` 返回错误信息；交给全局异常处理。
- 兜底 `Exception.class` 处理器返回「服务器异常」。

## 九、新增功能模块标准流程

以新增一个业务模块为例，按以下顺序，每步都遵循上面的分层与命名：

1. **建表**：在 `数据库设计.md` 登记表名与用途。
2. **Entity**：在 `entity/<模块>/` 下建实体，`@TableName` 映射，`extends BaseEntity`。
3. **Mapper**：在 `mapper/<模块>/` 下建 `XxxMapper extends BaseMapper<Xxx>`，加 `@Mapper`。
4. **Service**：建接口 `XxxService` + 实现 `XxxServiceImpl extends ServiceImpl<XxxMapper, Xxx>`。
5. **Controller**：建 `XxxController`，`@RequestMapping("/api/xxx")`，返回 `Result`。
6. **DTO/VO**：入参建 `dto/`，出参建 `vo/`。
7. **接口文档**：配合 Swagger 注解描述接口（如需要）。

## 十、代码风格

- 依赖注入统一用 **构造器注入**：`@RequiredArgsConstructor` + `private final Xxx xxx`。
- 类、方法、字段写 **JavaDoc 注释**，说明用途。
- 数据库查询优先用 MyBatis-Plus 的 `lambdaQuery()` / `lambdaUpdate()`，避免魔法字符串字段名。
- 魔法值（状态码、角色、常量字符串）尽量抽成常量，避免散落硬编码。
- 包名、目录、import 三者必须一致，改动命名后同步更新所有引用处。

  - 类型：`新增` / `重构` / `修复` / `删除` / `文档`。
