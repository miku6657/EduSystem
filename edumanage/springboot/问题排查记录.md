# 问题排查记录

> 记录开发过程中的问题、排查过程和解决方案。每解决一个问题，追加一条记录（最新在上或在下，保持一种即可）。

---

## 2026-09-08 无法解析符号 'BaseEntity'

- **问题**：实体类报「无法解析符号 'BaseEntity'」
- **原因**：`Teacher.java` 的 import 写成了 `com.keshe.edumanage.common.entity.BaseEntity`（该包不存在）。`BaseEntity` 实际位于 `com.keshe.edumanage.entity.BaseEntity`。
- **解决**：把 `Teacher.java` 的 import 改为 `com.keshe.edumanage.entity.BaseEntity`。
- **涉及文件**：`entity/base/Teacher.java`

---

## 2026-09-08 无法解析符号 'User'

- **问题**：报「无法解析符号 'User'」
- **原因**：`User.java` 的包名被改成了 `entity.system`，但目录仍是 `sys/`、`Role.java` 及 4 处 import 还停在 `entity.sys`，包名 / 目录 / 引用三者不一致。
- **解决**：统一包名为 `system`：目录 `sys` → `system`；`Role.java` 包名改 `system`；`UserMapper` / `UserService` / `UserServiceImpl` / `UserController` 的 import 从 `entity.sys.User` 改成 `entity.system.User`。
- **涉及文件**：`entity/system/{User,Role}.java` 及上述 4 个引用文件

---

## 2026-09-08 系统找不到指定的路径 entity\sys\Role.java

- **问题**：编译报「系统找不到指定的路径 entity\sys\Role.java」
- **原因**：`target/classes` 里残留着改名前的旧编译产物 `entity/sys/User.class`，IDEA 索引仍按旧路径查找。
- **解决**：`mvn clean` 清掉 target；IDEA 里 Invalidate Caches / Reload 刷新缓存。
- **涉及文件**：无源码改动，清理构建产物

---

## 2026-09-08 找不到符号 UserMapper

- **问题**：`UserServiceImpl` 报「找不到符号 类 UserMapper」
- **原因**：`UserMapper` 移到了 `mapper.system` 包，但 `UserServiceImpl` 的 import 还是 `com.keshe.edumanage.mapper.UserMapper`。
- **解决**：import 改为 `com.keshe.edumanage.mapper.system.UserMapper`。
- **涉及文件**：`service/UserServiceImpl.java`

---

## 2026-09-08 无法解析 UserService 中的方法 findByUsername

- **问题**：`AuthController` 报「无法解析 'UserService' 中的方法 'findByUsername'」
- **原因**：`UserService` 里只有 `getByUsername`，而新写的 `AuthController` 调的是 `findByUsername`，方法名不一致。
- **解决**：统一方法名为 `findByUsername`（接口 + 实现 + `UserController` 调用处同步修改）。
- **涉及文件**：`service/UserService.java`、`service/UserServiceImpl.java`、`controller/UserController.java`

---

## 2026-09-08 编译报 userMapper 未被默认构造函数初始化（待处理）

- **问题**：`mvn compile` 报 `UserServiceImpl.java:[23] 变量 userMapper 未被默认构造函数初始化`
- **原因**：命令行 Maven 编译时 Lombok 注解处理器未生效，`@RequiredArgsConstructor` 没生成构造函数，`private final UserMapper userMapper` 未初始化。（IDEA 装了 Lombok 插件并开启 annotation processing 则不会报）
- **状态**：待处理 —— 需在 `pom.xml` 给 `maven-compiler-plugin` 配置 `annotationProcessorPaths`（Lombok）。
- **涉及文件**：`pom.xml`（待改）、`service/UserServiceImpl.java`

---

## 2026-09-08 无法解析 Result 中的方法 fail

- **问题**：`AuthController` 报「无法解析 'Result' 中的方法 'fail'」
- **原因**：`Result` 类只有 `success` / `error`，没有 `fail` 方法，而 `AuthController` 登录逻辑里调用了 `Result.fail(...)`。
- **解决**：给 `Result` 新增静态方法 `fail(String message)`（状态码 500，与 `error` 一致）。
- **涉及文件**：`common/result/Result.java`

---

## 2026-09-08 JWTUtil 目录与包名不一致

- **问题**：`JWTUtil.java` 的包声明是 `com.keshe.edumanage.util`（单数），但文件所在目录却是 `utils`（复数），目录与包名对不上（会导致「程序包不存在」）。
- **原因**：目录命名 `utils` 与全工程单数命名约定（`controller`/`service`/`mapper`/`entity` 等）不一致。
- **解决**：把目录 `utils` 重命名为 `util`，与包声明及 `AuthController`、`JwtAuthenticationFilter` 的 import（均为 `util`）对齐。
- **涉及文件**：目录 `com/keshe/edumanage/utils` → `util`（仅含 `JWTUtil.java`）
